## 后续功能候选（按价值排序，未立项）

> 来源：M3 裁剪项 + 使用反馈。每个候选立项时再补 `docs/plan/m{N}/` 三件套。

1. **系统托盘常驻 + 全局快捷键唤起** —— 管理面板类工具的自然形态，关窗不退程序
2. **进程资源曲线** —— 详情侧栏增加 CPU/内存最近 60s 迷你折线（轮询数据已有，纯前端）
3. **快照 diff 高亮** —— 新出现/刚消失的进程短暂标记，快速发现"谁又被拉起来了"
4. **safe 级别批量结束** —— 孤儿视图多选清理；仅限 safe 级别且逐条确认摘要，不破 M2 安全模型
5. **关注端口通知** —— 关注端口被新进程占用时 Toast 提醒（防"端口又被占了"）
6. **开机自启** —— tauri autostart 插件，配合托盘才有意义
7. **自动更新** —— tauri updater + 发布渠道；需要签名与更新服务器，成本较高
8. **导出/复制快照** —— 一键复制进程/端口清单为文本，方便贴 issue 或聊天记录

暂缓：远程主机管理、服务/计划任务管理（超出产品定位，见 design-spec 第 2 节）。

## 关键决策

| 决策 | 结论 | 依据 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | 系统 API 访问 + 小体积；见 design-spec 5.1 |
| 数据采集 | `sysinfo` + `netstat2` | 成熟库，不自研；端口直接映射 PID |
| 前后端数据粒度 | 单次全量快照 `ProcessSnapshot` | 进程/端口联动视图共享一份数据，避免页间不一致 |
| 杀进程流程 | 一律经确认 Dialog，按安全分级区分确认强度 | 核心卖点是"准确判断能否杀" |
| 视觉体系 | 复用 `workbench-design-system.md` 两套主题 token | 用户既有设计体系，禁止新造品牌色 |

## 原则对齐（AGENTS.md）

- 不保留向后兼容；每个里程碑选择满足当前需求的最简单实现。
- M1 必须先打通最小端到端，后续里程碑只增不拆。
- 新增依赖前检查现有依赖。
