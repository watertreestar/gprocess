# M12 句柄占用 Agent 归因

## 目标

在按文件路径查找占用进程时，识别常用 Agent 的直接占用及父进程关联，给出可追溯的证据；避免将 Restart Manager 的空结果误读为文件无人占用。

## 范围

- 输入模糊文件名或目录名，默认在用户目录中有限量搜索候选；可进入匹配目录逐级浏览，选中文件后再查占用。仅查询存在的普通文件；不存在的路径和目录不能直接查占用。
- 识别 Claude Code、Codex、Cursor、Windsurf、Qoder、OpenCode、Aider、Agent Browser 的精确进程名或已采集脚本标记；父进程命中仅显示“关联”。
- 查询结果核实进程启动时间后才展示归因并允许“查看 / 结束”；结束仍走原有安全确认。
- 不做全系统句柄枚举、目录扫描、自动解锁；未识别不等于排除 Agent 相关性。

## 验收标准

1. 输入部分文件名能在用户目录范围找出候选文件和目录；进入目录可浏览子项，点击文件查询占用；搜索达到上限须明确提示结果不完整。
2. 持有已知文件句柄时可以查到对应进程，关闭句柄后不再列出；路径不存在或为目录时显示错误。
2. 命中明确 Agent 进程名/脚本时展示“占用”及证据；仅父进程命中时展示“关联”及证据；node/vite 等通用运行时不误报。
3. 空结果表述为“本次未发现可见占用”，而不是断言无人占用；修改路径立即清除旧查询结果。
4. PID 身份无法核实时不显示归因，且禁用“查看 / 结束”；杀前评估流程保持不变。
5. Rust 测试、Clippy、前端构建通过；桌面客户端人工验证查询交互、空态与 Agent 标签。
