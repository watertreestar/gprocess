# M10 判定反馈采集

## 目标

为后续小分类器（M11 候选）积累训练样本：用户对孤儿判定有异议时，一键上报进程特征 + 人工标签，落盘本地 JSONL。规则修复（M9）覆盖已知误判后，样本将来自长尾模糊案例。

## 范围

- 后端 `record_feedback` 命令：采集目标进程当前快照（含孤儿判定、脚本标记、父身份、端口状态）+ 标签 + 备注，追加写 `%APPDATA%/com.gprocess.app/feedback.jsonl`，返回累计样本数
- 详情页孤儿判定区新增「判定有误」入口：三种标签（误判为孤儿 / 来源分类错误 / 漏判）+ 可选备注
- 样本文件直接用文本编辑器查看（不单独做浏览 UI）
- 不做：模型训练与推理集成（等样本积累后立项）、样本上传/同步

## 验收标准

- [ ] 选中一个进程，点「判定有误」选标签提交，`feedback.jsonl` 新增一行且包含进程名/PID/标签/时间戳/特征
- [ ] 重复提交返回累计样本数并展示
- [ ] 未选标签时提交按钮禁用
- [ ] cargo test / clippy / npm build 全绿

## 已知限制

- 样本判定结果按提交时的快照采集，不含用户豁免名单（按默认判定记录）
- 文件为本地 JSONL，无并发写保护（单用户桌面场景可接受）
