# M2 孤儿判定与杀前评估

## 目标

实现产品的核心卖点：自动识别孤儿进程，并为任意进程给出可解释的杀前安全评估，让用户"准确判断是否可以杀"。

## 范围

**包含**

- 后端 `assess_process(pid)`：孤儿判定（含 PID 复用排除）+ 四级安全分级 + 影响面（子孙树、占用端口）
- 后端 `kill_tree(pid)`：自底向上结束整个子孙树
- 进程页：疑似孤儿标记（低饱和 warning 背景 + Badge）、「疑似孤儿」「监听端口」快捷过滤
- 详情侧栏：孤儿判定依据、进程树（父链 + 子孙，可跳转）、杀前评估级别与逐条理由
- 确认 Dialog 升级：按级别区分确认强度（`danger` 需输入 PID 确认，`forbidden` 按钮禁用）
- 结束进程树操作入口

**不包含（M3）**

- 孤儿运行时长阈值可配置（M2 用默认 30 分钟常量）
- 批量结束、提权

## 验收标准

1. 典型场景复现：`cmd` 中启动 `node` dev server 后关闭终端，进程页将该 node 进程标为疑似孤儿，判定依据展示"父进程已退出"。
2. PID 复用不误报：构造父 PID 被新进程复用的场景，判定仍正确（`pid_reused=true`）。
3. 系统关键进程（如 `csrss.exe`）的结束按钮禁用并说明原因。
4. 有子进程 / 监听端口的进程弹出包含完整影响面的确认 Dialog；`danger` 级别必须输入 PID 才能确认。
5. 结束进程树后，子孙进程全部退出，关联端口释放。
